title: "Verify webhook signatures"
description: "Authenticate Formbrew webhook payloads and protect your receiver from tampering and replay attacks."
---

Never trust a webhook payload until you verify its signature and timestamp. Signature validation proves that the sender signed the request with your endpoint secret and that its exact body has not changed in transit.

TLS protects a request while it travels over the network. The webhook signature independently authenticates the sender and payload at your application boundary.

## Signature format

Formbrew calculates HMAC-SHA256 over this byte sequence, using the complete `whsec_...` secret as the key:

```text
<Formbrew-Timestamp>.<exact raw request body>
```

It sends the lowercase hexadecimal digest as:

```text
Formbrew-Signature: v1=<64 lowercase hexadecimal characters>
```

The timestamp text and period are UTF-8 bytes. The body portion is the exact request body received over HTTP. Whitespace, line endings, character encoding, or JSON key ordering changes produce a different signature.

## Validation procedure

1. Read `Formbrew-Timestamp` and require a nonnegative integer in Unix seconds.
2. Reject timestamps more than five minutes in the past or future.
3. Read the body without decoding, parsing, reformatting, or serializing it.
4. Compute HMAC-SHA256 with the endpoint's complete `whsec_...` secret.
5. Compare the expected and received signatures in constant time.
6. Only after the comparison succeeds, parse and validate the JSON payload.
7. Require `Formbrew-Delivery-Id` to match the payload `id` and `Formbrew-Event` to match the payload `type`.
8. Deduplicate the accepted delivery ID in durable storage.

The timestamp check limits replay attempts, but it does not replace delivery-ID deduplication. An attacker can replay a signed request within the accepted time window.

## Receiver example

This example uses the Web Crypto API and the standard `Request` and `Response` types, so it runs in Node.js 20 or later, Bun, Deno, and edge runtimes without a framework. `crypto.subtle.verify()` compares the signature for you, so the code never compares signature strings itself.

{/* docs-check: typecheck */}
```ts
type VerifyFormbrewSignatureOptions = {
  now?: Date;
  rawBody: Uint8Array;
  secret: string;
  signature: string | null;
  timestamp: string | null;
  toleranceSeconds?: number;
};

type FormbrewWebhookEvent = {
  createdAt: string;
  data: {
    formId: string;
    submission: {
      createdAt: string;
      formSchemaVersion: number;
      id: string;
      metadata: Record<string, unknown> | null;
      origin: string | null;
      userAgent: string | null;
      values: Record<string, unknown>;
    };
  };
  id: string;
  type: string;
  version: number;
};

// Replace with your own durable, idempotent storage or queue.
declare function enqueueDeliveryOnce(event: FormbrewWebhookEvent): Promise<void>;

const encoder = new TextEncoder();
const maxBodyBytes = 1_048_576;

export async function verifyFormbrewSignature(
  options: VerifyFormbrewSignatureOptions,
): Promise<boolean> {
  const { signature, timestamp } = options;
  const toleranceSeconds = options.toleranceSeconds ?? 300;

  if (!timestamp || !/^\d+$/.test(timestamp)) {
    return false;
  }

  const timestampSeconds = Number(timestamp);
  const nowSeconds = Math.floor((options.now ?? new Date()).getTime() / 1000);

  if (!Number.isSafeInteger(timestampSeconds)) {
    return false;
  }

  if (Math.abs(nowSeconds - timestampSeconds) > toleranceSeconds) {
    return false;
  }

  const digest = /^v1=([a-f0-9]{64})$/.exec(signature ?? "")?.[1];

  if (!digest) {
    return false;
  }

  const signatureBytes = new Uint8Array(32);

  for (let index = 0; index < signatureBytes.length; index++) {
    signatureBytes[index] = Number.parseInt(digest.slice(index * 2, index * 2 + 2), 16);
  }

  const prefix = encoder.encode(`${timestamp}.`);
  const signedContent = new Uint8Array(prefix.length + options.rawBody.length);
  signedContent.set(prefix);
  signedContent.set(options.rawBody, prefix.length);

  const key = await crypto.subtle.importKey(
    "raw",
    encoder.encode(options.secret),
    { hash: "SHA-256", name: "HMAC" },
    false,
    ["verify"],
  );

  return await crypto.subtle.verify("HMAC", key, signatureBytes, signedContent);
}

export async function handleFormbrewWebhook(request: Request, secret: string): Promise<Response> {
  const rawBody = new Uint8Array(await request.arrayBuffer());

  if (rawBody.length > maxBodyBytes) {
    return new Response(null, { status: 413 });
  }

  const valid = await verifyFormbrewSignature({
    rawBody,
    secret,
    signature: request.headers.get("formbrew-signature"),
    timestamp: request.headers.get("formbrew-timestamp"),
  });

  if (!valid) {
    return new Response(null, { status: 401 });
  }

  const event = JSON.parse(new TextDecoder().decode(rawBody)) as FormbrewWebhookEvent;

  if (
    event.type !== "submission.created" ||
    event.version !== 1 ||
    event.id !== request.headers.get("formbrew-delivery-id") ||
    event.type !== request.headers.get("formbrew-event")
  ) {
    return new Response(null, { status: 400 });
  }

  await enqueueDeliveryOnce(event);

  return new Response(null, { status: 204 });
}
```

Load the secret from server-side secret storage and pass it to the handler. For example, with Bun's HTTP server:

```ts
Bun.serve({
  fetch: (request) => handleFormbrewWebhook(request, process.env.FORMBREW_WEBHOOK_SECRET ?? ""),
});
```

With Express, mount `express.raw()` on the webhook route before any JSON body parser consumes it. `express.raw()` provides the body as a `Buffer`, which is a `Uint8Array`:

```ts
app.post("/webhooks/formbrew", express.raw({ type: "application/json" }), async (request, response) => {
  const valid = await verifyFormbrewSignature({
    rawBody: request.body,
    secret: process.env.FORMBREW_WEBHOOK_SECRET ?? "",
    signature: request.get("Formbrew-Signature") ?? null,
    timestamp: request.get("Formbrew-Timestamp") ?? null,
  });

  if (!valid) {
    response.sendStatus(401);
    return;
  }

  const event = JSON.parse(request.body.toString("utf8"));
  // Validate the event, then durably enqueue it before acknowledging.
  response.sendStatus(204);
});
```

If middleware has already parsed the body into an object, serializing that object again is not safe. Configure your framework to retain the original bytes for this route.

## Secret rotation

Rotate a secret immediately if it may have been exposed. On the form's **Webhooks** page, select **Rotate secret** on the endpoint, then **Rotate and reveal**. Formbrew shows the new secret once. The previous secret stops working for new attempts immediately, and rotation cancels deliveries that are queued or waiting to retry. An attempt already in progress may finish with the previous secret.

For a planned rotation:

1. Confirm no deliveries are queued or waiting to retry, then choose a quiet period.
2. Rotate the secret and copy it immediately.
3. Configure receivers to accept the new and previous secrets temporarily.
4. Send a new test submission and confirm it validates with the new secret.
5. Remove the previous secret after all requests that were already in progress have finished.

This cutover is not atomic. A new delivery created after rotation but before every receiver has the new secret can receive a permanent `401`. Formbrew does not provide an overlapping-secret grace period, so do not rotate during active traffic if that loss is unacceptable. Retaining the previous secret only protects requests that were already in progress.

Disabling the endpoint does not preserve queued deliveries. Disabling and rotation both cancel pending work, and submissions accepted while the endpoint is disabled do not create deliveries for it.

Never identify a secret by storing its full value in logs. The dashboard shows the last eight characters of the current secret; compare them with the secret your receiver uses to check which configuration you deployed.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| Every signature fails | Wrong endpoint secret, or a body parser changed the raw bytes |
| Only some signatures fail | Multiple receiver instances use different secrets |
| Timestamp is always stale | Server clock is incorrect, or too much processing happens before validation |
| Valid events cause duplicate work | Your receiver does not store delivery IDs with a durable unique constraint |
| Formbrew does not retry | Receiver returned a permanent `4xx` or `3xx` response |
| Deliveries never arrive | The endpoint is disabled, the URL is not reachable over public HTTPS, or the form has more enabled endpoints than the plan allows |
