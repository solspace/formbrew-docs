The Public API is the browser-safe API behind the hosted embed, the JavaScript and React SDKs, plain HTML forms, and custom clients. You don't need an API key: a public form token identifies the form, and the form's allowed origins control where you can use it.

```text
https://api.formbrew.com/v1
```

The Public API and the [Management API](/api-reference/management-overview) are separate. Each serves only its own paths, so a Management API path sent to the Public API base URL returns `404`.

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/health` | Check that the Public API is available. |
| `GET` | `/v1/openapi.json` | Download the Public API OpenAPI document. |
| `GET` | `/v1/forms/{token}` | Fetch the render-safe definition of a published form. |
| `POST` | `/v1/forms/{token}/submit` | Validate and create a submission. |

The endpoint reference in this section is based on the [Public API OpenAPI document](https://api.formbrew.com/v1/openapi.json). For origin rules, content types, errors, and rate limits, see [Public API requests](/api-reference/public-requests).

## Access model

Both form endpoints require:

- A known public form token that isn't revoked or expired.
- A form with `PUBLISHED` status.
- An `Origin` header, or a `Referer` header when `Origin` is absent, that matches one of the form's allowed origins.
- A request within the form's [rate limits](/api-reference/public-requests#rate-limits).

Public form tokens are publishable identifiers, so you can include them in frontend code. They don't grant access to the Management API. See [Tokens and origins](/integrations/public-access) for how tokens and allowed origins work together.

## Fetch a definition

```bash
curl 'https://api.formbrew.com/v1/forms/YOUR_PUBLIC_FORM_TOKEN' \
  --header 'Origin: https://www.example.com'
```

The `data` object contains the form's display settings, `schemaVersion`, `honeypotFieldName`, and ordered field definitions. It excludes workspace details, allowed origins, token records, submissions, and timestamps.

```json
{
  "data": {
    "id": "frm_123",
    "name": "Contact",
    "slug": "contact",
    "schemaVersion": 3,
    "submitButtonLabel": "Send",
    "successMessage": "Thanks. We will be in touch.",
    "honeypotFieldName": "_fb_a8f31c_url",
    "fields": []
  }
}
```

## Create a submission

```bash
curl 'https://api.formbrew.com/v1/forms/YOUR_PUBLIC_FORM_TOKEN/submit' \
  --header 'Content-Type: application/json' \
  --header 'Origin: https://www.example.com' \
  --data '{
    "values": {
      "email": "hello@example.com"
    },
    "metadata": {
      "source": "contact-page"
    }
  }'
```

An accepted request returns `201`. The `message` value is the form's success message.

```json
{
  "data": {
    "id": "sub_123",
    "message": "Thanks. We will be in touch."
  }
}
```

## Side effects

{/* docs-check: production-setting email.delivery */}

Formbrew stores an accepted submission, counts it toward your workspace's monthly usage, and queues it for each active [webhook](/webhooks/overview) endpoint on the form. Delivery happens after the response, so a delivery failure never changes an accepted submission.

<Note>
  The Public API doesn't support idempotency keys. If you repeat a request that Formbrew already accepted, it creates another submission.
</Note>
