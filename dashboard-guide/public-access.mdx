---
title: "Public access"
description: "Configure allowed origins and public form tokens."
---

Open a form and select **Public access** to control who can load and submit it. Public access has two controls that work together:

- **Allowed origins** define which websites may fetch and submit the form.
- **Public form tokens** identify the form in public URLs and SDK configuration.

You must also publish the form. A token by itself does not make a draft form public.

## Allowed origins

Add one allowed origin for every website environment that will use the form. An allowed origin contains only the scheme, hostname, and optional non-default port.

```text
https://www.example.com
https://app.example.com
http://localhost:5173
```

Type an origin and press Enter, Space, or Tab to add it. You can also paste several origins separated by spaces, then press Enter. Select **Save changes**, or press ⌘S on macOS or Ctrl + S on other systems, to save the list.

- If you omit the scheme, Formbrew uses `https://`.
- Formbrew removes paths, query strings, and fragments when you add an origin.
- Origins cannot contain a username or password.
- Wildcards are not supported. A value such as `https://*.example.com` does not match requests from its subdomains. Add each subdomain explicitly.

<Warning>
  `https://example.com` and `https://www.example.com` are different origins. Localhost ports are also distinct, so add the exact port used by your development server.
</Warning>

A published form must keep at least one allowed origin. To remove the last one, set the form to **Draft** first.

The browser supplies `Origin` automatically. The public API uses `Referer` only when `Origin` is absent. Non-browser clients must send the configured website origin explicitly.

## Public form tokens

Select **Add new access token**, enter an optional **Token name**, and select **Generate token**. Use names such as `Production website` or `Local development` so you can identify where you use a token. If you leave the name blank, Formbrew generates a random name.

After Formbrew generates the token, select **Copy token**. You can copy it again later from the token table or the **Integration** page.

The token table shows each token's value, name, creation time, and last use. It also shows whether a token is **Active**, **Revoked**, or **Expired**. Tokens created in the dashboard do not expire.

<Note>
  Public form tokens are safe to include in HTML and browser JavaScript. They identify a form; they are not account credentials or Management API secrets.
</Note>

Owners, admins, and editors can view and manage tokens. Viewers cannot see tokens.

## Revoke a token

Select **Revoke**, then select **Revoke token** to confirm. Revocation is immediate, and you cannot undo it. Requests that use a revoked token receive an unauthorized response.

For a planned rotation, generate a new token and update your deployed websites first. Then revoke the old token.

## Get integration code

Select **Integration** in the form navigation to open the integration guide. It shows whether the form is published, has allowed origins, and has a usable token.

Choose **Embed**, **HTML**, **JavaScript**, or **React**, pick a token inside the example, and copy the code. See the [frontend quickstart](/integrations/quickstart) for details.

## Publish checklist

Before publishing, verify that:

- At least one allowed origin is saved.
- Every website hostname, including preview and development sites, has its own allowed origin.
- At least one active token exists for the integration.
- Field keys and option values are ready for downstream consumers.
- A real submission succeeds from the deployed website.
