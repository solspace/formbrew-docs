A native HTML form can submit directly to Formbrew without client-side JavaScript. Copy the generated example from **Integration** in the form builder because it includes your current field keys, choice values, honeypot name, and validation attributes.

## Native form

```html
<form id="formbrew-form" action="https://api.formbrew.com/v1/forms/YOUR_PUBLIC_FORM_TOKEN/submit" method="POST">
  <div aria-hidden="true" style="position:absolute;left:-10000px;">
    <label>
      Leave this field blank
      <input name="YOUR_HONEYPOT_FIELD_NAME" tabindex="-1" autocomplete="off" />
    </label>
  </div>

  <label>
    Email
    <input id="email" name="email" type="email" required />
  </label>

  <fieldset>
    <legend>Interests</legend>
    <label><input name="interests" type="checkbox" value="product" /> Product</label>
    <label><input name="interests" type="checkbox" value="pricing" /> Pricing</label>
  </fieldset>

  <button type="submit">Submit</button>
  <p id="form-status" aria-live="polite"></p>
</form>
```

The browser sends `application/x-www-form-urlencoded` by default. Formbrew normalizes repeated names, such as checkbox-group values, into arrays.

## After a native submission

A native submission answers with a page, not JSON:

- **Success:** the browser lands on a success page that Formbrew hosts. It shows the form's **Success message**. Refreshing it doesn't submit the form again. When the visitor posted from one of the form's allowed origins, the page links back to your site.
- **Error:** the browser shows an error page that Formbrew hosts, with the same status code and messages as the [JSON error](/integrations/submissions-and-errors#error-response). It asks the visitor to go back and try again. Browsers usually keep typed answers when going back, but they often drop chosen files.

On the Free plan, the hosted pages show a small Formbrew mark. Use progressive enhancement if the visitor should stay on your page.

### Your own success page

On a paid plan, you can send visitors to your own page after a successful native submission. Set **Success redirect URL** in the form settings, or `successRedirectUrl` through the Management API. The URL must be on one of the form's allowed origins.

Formbrew redirects to the URL exactly as you saved it and adds nothing to it, so answers never end up in browser history or your analytics. To recognize the redirect, put your own marker in the URL, for example `https://example.com/thanks?submitted=1`.

Native submissions use the hosted success page again when you remove the URL's origin from the allowed origins, or when the workspace moves to the Free plan. The URL stays saved. Errors always show the hosted error page.

### How Formbrew recognizes a native submission

A request is a native submission when its body is form-encoded or multipart and its `Accept` header lists `text/html`, which browsers send when they navigate. `fetch()`, the JavaScript and React SDKs, the embed, and curl don't ask for HTML, so they keep getting [JSON](/integrations/submissions-and-errors#successful-response). A JSON body always gets JSON.

## Field markup

The generated markup maps each field type to a native control:

| Field type | Control | Submitted value |
| --- | --- | --- |
| Text | `<input type="text">`, or `<textarea>` when the field is multiline | Text. Single-line fields replace line breaks with spaces. |
| Email | `<input type="email">` | Trimmed address |
| Number | `<input type="number">` with `step`, `min`, and `max` from the field settings | Decimal number text |
| Phone | `<input type="tel">` | Trimmed text |
| Website | `<input type="url">`, with an HTTPS pattern when the field requires HTTPS | Trimmed HTTP or HTTPS URL |
| Checkbox | `<input type="checkbox" value="true">` | `true` when checked; omitted when unchecked |
| Checkbox group | Checkboxes sharing the field key | Each option value |
| Radio group | Radio buttons sharing the field key | One option value |
| Select | `<select>` with an empty first option | One option value |
| Date/Time | `<input type="date">`, `<input type="time">`, or `<input type="datetime-local">` | `YYYY-MM-DD`, `HH:MM`, or `YYYY-MM-DDTHH:MM`, without a timezone |
| Hidden | `<input type="hidden">` at the start of the form, with the configured default value | Text |
| Confirm | The same kind of control as its target field, with the Confirm field's own key | Must match the target value |
| Content | Static headings, paragraphs, lists, and links | Nothing |

Checkbox fields also accept `on`, `1`, and `yes` as checked values. Keep option values exactly as generated; the API rejects values that are not current options.

## Honeypot

Use the `honeypotFieldName` from the form settings or public definition. The generated name starts with an underscore, such as `_fb_ab12cd34_url`. The input must:

- Be a normal text input, not `type="hidden"`.
- Be visually hidden from human visitors.
- Keep the generated field name.
- Stay empty.

A filled honeypot returns `400` with the generic message `Submission rejected.`

## Progressive enhancement

Intercept the native submit, send `FormData`, and handle the JSON response in place:

```html
<script>
  const form = document.querySelector("#formbrew-form");
  const status = document.querySelector("#form-status");

  form.addEventListener("submit", async (event) => {
    event.preventDefault();
    status.textContent = "Submitting...";

    try {
      const response = await fetch(form.action, {
        body: new FormData(form),
        method: "POST",
      });
      const payload = await response.json();

      if (!response.ok) {
        throw new Error(payload.message ?? "Submission failed.");
      }

      form.reset();
      status.textContent = payload.data.message;
    } catch (error) {
      status.textContent = error instanceof Error ? error.message : "Submission failed.";
    }
  });
</script>
```

`FormData` uses `multipart/form-data`. Formbrew accepts text entries but rejects file uploads with `400`. Error responses use a top-level `message`; see [submissions and errors](/integrations/submissions-and-errors).

## Metadata in flat forms

Names beginning with `_` become metadata keys without their first underscore:

```html
<input name="_source" type="hidden" value="contact-page" />
```

This produces metadata `{ "source": "contact-page" }`. Keep normal field keys free of a leading underscore.

## Origin and Content Security Policy

Native form posts send the page origin in the `Origin` header. If your site sets `Referrer-Policy: no-referrer` or `same-origin`, browsers send `Origin: null` for the native post instead, and Formbrew rejects it with `403`. Use the browser default `strict-origin-when-cross-origin`, or use progressive enhancement: `fetch()` requests always send the real origin.

If your site uses a Content Security Policy:

- Native submission requires `https://api.formbrew.com` in `form-action`. With a success redirect URL, also add the URL's origin, or `'self'` when it's the same site: browsers apply `form-action` to the redirect that follows the post.
- Progressive enhancement requires `https://api.formbrew.com` in `connect-src`.
- The generated honeypot wrapper uses an inline `style` attribute. If your policy blocks inline styles, hide the wrapper with a class in your own stylesheet instead.
